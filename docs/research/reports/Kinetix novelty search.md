# Kinetix wins on decomposition, not on savings

Kinetix's novelty is not the headline it was built around. "50–80 % fewer images than orbit/grid" is already in the literature: about 72 % fewer for a monocular toy drone, about 53 % at equal F-score for learned aerial planners, about 50–67 % for recent object NBV. "Monocular active reconstruction" and "foundation depth inside NBV" are claimed too, by ActMVS, FrontierNet and Next Best Sense. What remains open after a 2022–2026 search is a specific combination, plus three experimental contributions no paper has made. The combination is a relative-depth foundation model (Depth Anything V2) **scale-anchored online to the growing SfM model**, fused into a TSDF frontier score and **combined with an SfM-uncertainty score**, driving object-centric NBV on a **real indoor PX4/Jetson drone** whose images go to **unmodified COLMAP → MVS/3DGS**. The three experimental contributions are: (i) a same-planner comparison of monocular vs real 63 mm stereo that **separates depth-for-planning from depth-for-reconstruction** in a 2×2 design; (ii) a **threshold-referenced images-to-quality metric N@q**, normalised to a dense capture of the same object; (iii) a **four-tier realism protocol** (photoreal pool replay → continuous render → PX4 SITL → real flight) that measures how method rankings shift with realism. The paper should therefore lead with the decomposition and the protocol, and present the image saving as a result *consistent with* earlier reports, measured against the strongest baselines. The baselines need strengthening first: farthest-view sampling, a volumetric information-gain planner, FisherRF and one learned planner are missing from the current matrix. The natural venue is IEEE RA-L with an ICRA/IROS presentation; 3DV/CVPR fits only if the object set grows to hundreds of items.

## Five works define the neighbourhood, and each misses at least two Kinetix axes

The closest system is **Hestia** (WACV 2026). It is a learned, hierarchical, face-aware NBV policy trained in Isaac Lab with a Crazyflie model and deployed on a real drone with **an RGB camera only, plus a learned depth predictor (MASt3R/DUSt3R)**, on indoor objects. It reports 92 % coverage with 5 acquisitions where prior work needs 15, and 50 % lower Chamfer distance ([Hestia arXiv v3](https://arxiv.org/html/2508.01014v3)). It differs from Kinetix in ways that matter. Its real-world results are qualitative ("visibly better" point clouds). Its first three views are placed by hand to align the real and virtual frames. Localisation comes from external Lighthouse base stations. The reconstruction is MASt3R-SfM, not COLMAP. Its efficiency metric is coverage at a view budget ([Hestia HTML](https://arxiv.org/html/2508.01014)). Hestia already occupies "RGB-only, object-centric, real drone", so Kinetix cannot claim that triple. It can claim quantitative real-flight geometry against scanned GT, a standard photogrammetry output, and an explicit sensing study.

The closest monocular competitor is **ActMVS** (arXiv 2606.01367, May 2026), which calls itself "the first framework for monocular active reconstruction". It builds a view factor graph for MVS depth and claims "robust autonomous aerial reconstruction without depth sensors" — but on Replica scenes in Habitat and AirSim, with **no real deployment** ([ActMVS PDF](https://arxiv.org/pdf/2606.01367)). Its comparisons are revealing. ActMVS reaches 2.4 cm Chamfer on Room0 against 1.18 cm for RGB-D ActiveGS, at about four times the runtime. Replacing its MVS depth with single-image metric depth degrades Chamfer from about 2.4 cm to about 46 cm ([ActMVS PDF](https://arxiv.org/pdf/2606.01367)). That ablation is the strongest evidence in the literature that naive monocular depth is unreliable for planning, which makes Kinetix's SfM-anchored scale fit worth testing.

On the foundation-model side, **Next Best Sense** (arXiv 2410.04680) already puts **Depth Anything V2 / Metric3D V2** into an object NBV loop on a Kinova arm, with FisherRF on 3DGS. But it aligns scale and offset per object against **a real depth camera**, not against SfM ([Next Best Sense](https://arxiv.org/html/2410.04680v1)). **FrontierNet** (RA-L 2025) derives frontiers and information gain from posed RGB plus Metric3D v2 for scene exploration on Spot. It shows that classical planners "degrade significantly with predicted depth" ([FrontierNet](https://arxiv.org/html/2501.04597v2)). **Murre** (CVPR 2025) is the closest prior art for the "SfM sparse points → monocular depth → TSDF" chain, but it is offline and plans no views ([Murre](https://openaccess.thecvf.com/content/CVPR2025/papers/Guo_Multi-view_Reconstruction_via_SfM-guided_Monocular_Depth_Estimation_CVPR_2025_paper.pdf)).

The classical precedent cannot be skipped. **Huang et al.'s toy drone** (arXiv 1705.01010) is a monocular Bebop that plans on 640×368 online MVS and reconstructs from 1920×1080 stills. It is real indoors (Vicon) and outdoors, and it used **108 adaptive views against 390 for a dense rectangle pattern at similar accuracy**: about 72 % fewer, a reduction already inside Kinetix's target range ([ar5iv](https://ar5iv.arxiv.org/html/1705.01010)).

The benchmark landscape has one new, dangerous neighbour. **ObjView-Bench** (Bonn, arXiv 2605.10707, May 2026) argues that "difficulty, budget, and reachability constraints substantially change method rankings and failure modes" — Kinetix's tiered-protocol argument — but for a tabletop arm. It uses depth/coverage metrics on a 128-view Tammes sphere over 5,691 Objaverse++ objects, has no photoreal SfM and no drone, and promises its code on acceptance ([ObjView-Bench](https://arxiv.org/html/2605.10707)).

A pattern runs through the table. Every geometric evaluator in this literature scores its *own* reconstruction: back-projected depth, an online 3DGS, or a neural surface. **None of the surveyed papers found to evaluate the selected image set through an unmodified COLMAP SfM→MVS pipeline against a GT mesh** ([radiance-field NBV catalogue: FisherRF](https://arxiv.org/abs/2311.17874v1), [ActiveGS](https://arxiv.org/pdf/2412.17769), [VIN-NBV](https://arxiv.org/html/2505.06219v3)). This is a quiet but real gap. Photogrammetric failure modes — registration, triangulation angle, feature overlap — are invisible to radiance-field uncertainty methods.

## Six candidate claims are taken; five remain open

The taken claims fall fast once the numbers are lined up. Image-reduction factors against fixed patterns already span Kinetix's target. The toy drone saves about 72 % against a dense rectangle and about 69 % outdoors ([ar5iv](https://ar5iv.arxiv.org/html/1705.01010)). Liu et al. (SIGGRAPH Asia 2022) match F-score with **764 vs 1,610 images**, about 53 % fewer ([arXiv 2209.10174](https://arxiv.org/pdf/2209.10174)). NeRF Director reaches 33 dB with 70 views where random needs 150 ([arXiv 2406.08839](https://arxiv.org/abs/2406.08839v1)). PUN reaches comparable accuracy "using half of the viewpoints" ([arXiv 2506.14856](https://arxiv.org/pdf/2506.14856)). Next-Best Stereo reconstructs Middlebury models from 3.8–4.4 % of the views ([BMVC 2016](https://www.bmva-archive.org.uk/bmvc/2016/papers/paper065/paper065.pdf)). A reviewer who knows any of these will read a bare "50–80 %" claim as incremental.

| N@q: images to reach q × dense-capture F-score | **Open** as a formalisation | nearest: SCONE coverage AUC ([link](https://arxiv.org/pdf/2208.10449)), Smith 2018 quality-vs-views curves ([link](https://download.hrz.tu-darmstadt.de/media/FB20/GCC/paper/Smith-2018-APP.pdf)) |

| Quantitative indoor object NBV on a PX4/Jetson drone, evaluated through unmodified COLMAP/3DGS | **Open** | nearest: Hestia, toy drone |

Two of the open items need care. The mono-vs-stereo study is an **experimental-design novelty, not an algorithmic one**. It is still the clearest gap: no paper keeps one NBV planner fixed and swaps monocular, small-baseline stereo and RGB-D. Cross-paper comparisons such as ActMVS-vs-ActiveGS mix planners and representations ([ActMVS](https://arxiv.org/pdf/2606.01367)). The physics makes the question non-trivial. ZED Mini depth error is about 1 % at 2 m ([Stereolabs](https://support.stereolabs.com/hc/en-us/articles/1500008533841-For-the-depth-sensing-what-is-the-range-for-the-ZED-cameras-in-terms-of-measuring-distances-and-the-accuracy-of-the-detection)), roughly the size of a 1 %-of-object F-score threshold. The 63 mm baseline subtends only about 2.4° at 1.5 m, against 15–30° between planned views. The prediction is that stereo helps planning far more than final accuracy, and that prediction is falsifiable. Second, the SfM-anchored prior claim is narrow and must stay narrow. "Foundation depth for NBV" is gone, but "*scale from the reconstruction itself*, so the planner needs no depth sensor and no metric depth model" is not. MonoSpheres deliberately avoids learned depth because it "struggle[s] to provide real-time onboard performance and reliable generalization" ([MonoSpheres](https://arxiv.org/html/2511.17299)), and ActMVS's 46 cm ablation backs that worry. Kinetix's scale fit is the answer to that argument, so the paper must show the anchoring is what makes the prior usable.

## Recommended contribution list and baselines for an RA-L submission

The contribution list below follows the open items. Each statement is scoped to the strongest prior claim it has to survive.

| # | Contribution statement (paper wording) | Must be backed by |
|---|---|---|
| C1 | "A monocular next-best-view method for single-object photogrammetry that anchors a relative-depth foundation model to the scale of the incremental SfM reconstruction and fuses it into a TSDF frontier score, combined with an SfM-uncertainty score; it needs no depth sensor or metric-depth model for planning." | Ablation: scale-fit vs a metric model without SfM vs no prior; scorer terms alone vs combined |
| C2 | "The first controlled study, to our knowledge, of monocular versus small-baseline stereo sensing within one NBV planner, which separates the value of depth for *planning* from its value as *input to reconstruction*." | 2×2 presets `mono` / `stereo_plan` / `stereo_full` / `oracle_depth`, on T0 and on real flights |
| C3 | "N@q, an images-to-quality metric that reports the number of images a capture strategy needs to reach a fixed fraction of the F-score of a dense capture of the same object, alongside standard Chamfer, F-score and coverage-AUC metrics." | Sensitivity to q and to the dense-reference density; agreement with fixed-budget tables |
| C4 | "A four-tier evaluation protocol — photoreal view-pool replay, continuous rendering, PX4 SITL flight, and real indoor flight — with which we quantify how NBV method rankings and image savings change as realism increases." | Rank correlation of methods between tiers; per-tier N@q |
| C5 | "A real-flight evaluation on a PX4/Jetson quadrotor with scanned ground truth, and released view pools, digital twins, evaluation code and baselines." | Quantitative real Chamfer/F-score; release |

The image saving belongs in the results, not the contribution list. The suggested sentence is: "at equal quality Kinetix needs X % fewer images than the best fixed pattern and Y % fewer than the best adaptive baseline, consistent with prior reports (~53–72 %)." The saving must be computed against the strongest baseline. Huang's own table shows why: a 858-view multi-angle grid did *worse* than the 108-view NBV, so a naive "88 % fewer" was available against a weak pattern ([ar5iv](https://ar5iv.arxiv.org/html/1705.01010)).

Reviewers will expect four families of baselines, and the current matrix (`orbit_1ring`, `orbit_3ring`, `grid_hemisphere`, `random`, `coverage_oracle`) covers only the first. **Fixed patterns** are already in, and the dense multi-ring orbit at matched ground sampling distance is the one that counts. **Farthest-view sampling** is cheap and is shown to be strong: NeRF Director needed 70 views with it versus 150 random ([NeRF Director](https://arxiv.org/abs/2406.08839v1)). **A classical volumetric information-gain planner** in the Delmerico/Isler family is the RA-L default ([Delmerico et al.](https://infoscience.epfl.ch/record/228469)). **One learned planner** is needed, preferably MA-SCVP: its code is public, it is the Bonn line that ObjView-Bench benchmarks, and it is pool-native ([MA-SCVP](https://github.com/psc0628/MA-SCVP)). GenNBV is the drone-flavoured alternative ([GenNBV](https://arxiv.org/html/2402.16174v2)). **FisherRF** selects views from a candidate pool with RGB only, which makes it the radiance-field representative that runs unchanged on T0 pools ([FisherRF](https://arxiv.org/abs/2311.17874v1)). Hestia and VIN-NBV are the ideal object-NBV comparisons if their code runs, but their release status was not verified. An **explore-then-exploit** variant (orbit seed, then coverage of weak regions, after Peng & Isler and the toy drone) answers the "this is just the 2018 pipeline at small scale" objection.

On venue, RA-L with an ICRA or IROS presentation is the right home. SCVP, Bag of Views, ActiveGS and ActiveSplat appeared there, and its reviewers reward exactly the system + real-robot + open-code + benchmark mix ([Bag of Views](https://arxiv.org/abs/2307.05832), [ActiveGS](https://arxiv.org/pdf/2412.17769)). The Bonn group (SCVP, MA-SCVP, ObjView-Bench, DM-OSVP++, ActiveGS) is the reviewer pool most likely to read the paper, so the framing should make Kinetix the **aerial, photoreal, monocular-SfM complement** to ObjView-Bench, not a rival. CVPR/3DV is viable only if the object set reaches hundreds of items with learned baselines, the precedent set by GenNBV and UrbanScene3D. ISPRS P&RS fits a version that leads on photogrammetric accuracy (C2 + C3), though no 2023–26 drone object-NBV paper there was verified.

## Eight plan changes follow directly from the findings

The headline must move first. `docs/benchmark.md` and `docs/research/idea.md` frame the paper around "50–80 % fewer images at equal quality". That claim should become a reported result, and C1–C5 should become the claims. The `related_work.md` gap "monocular-only … has no direct prior" must also be rewritten, because ActMVS, MACARONS, Hestia, Next Best Sense and FrontierNet all contradict it as worded.

The baseline set needs four additions to `docs/benchmark.md` §1: `fvs` (farthest-view sampling over the pool), `volumetric_ig` (rear-side or unobserved-voxel entropy on the same TSDF), `fisherrf` (offline over the pool, RGB-only), and one learned planner (`ma_scvp`, or `gennbv` if Isaac Gym is easier to integrate). An `explore_exploit` variant should be added if K3 time allows. Every one of them selects from a candidate set, so they slot into the existing T0 `PoolRig` with no new rig code. That makes pool replay a strength, not just a convenience.

View-pool compatibility needs two changes. First, add a **128-view Tammes-sphere pool layout** next to `rings:4x60`, with drone reachability masks (no views below the floor plane or inside walls), so that results can be read against ObjView-Bench's canonical protocol ([ObjView-Bench](https://arxiv.org/html/2605.10707)). Second, include a few objects drawn from Objaverse++, Google Scanned Objects or OmniObject3D among the 8–10 sim scenes, so the object set overlaps with community pools. Pool density is already flagged as a parameter in ADR-K02. It now matters twice, because N@q's reference `F_ref` depends on it. The paper therefore needs a sensitivity row: N@q against a 120-, 240- and 360-view dense reference.

The metric set needs widening, not replacing. Keep N@q as the headline, and add three things next to it: coverage AUC over the image sequence (the SCONE/GenNBV convention), quality at fixed budgets K=5 and K=30 (ObjView-Bench's budgets), and N@q for q ∈ {0.9, 0.95}. With these, a reviewer can map Kinetix onto any prior table. Report F-score at both relative τ (already planned) and one absolute τ in millimetres for the real objects. Add a tier-transfer metric: **Kendall's τ between method rankings at T0 and at T1/T2/T3**, plus the change in N@q per tier. This turns C4 from a description into a measured result, the aerial analogue of ObjView-Bench's "rankings change" claim.

C1 needs two ablations in `benchmark.md` §4 that isolate the anchoring itself. The first is `plan_depth=mono_metric_noanchor`: Metric3D v2 or Depth Pro used directly, as FrontierNet does. The second is `plan_depth=mono_stereo_anchor`: DA-V2 scale-fit to ZED depth, as Next Best Sense does with its sensor. If SfM anchoring does not beat both, C1 collapses to engineering. A timely, optional third arm swaps in Depth Anything 3 or VGGT multi-view depth with drone-pose scale. Depth Anything 3 is reported to beat DA-V2 and VGGT ([DA3](https://arxiv.org/html/2511.10647v1)), and no drone NBV loop uses either yet.

The real-flight tier must be quantitative. Hestia's real results are qualitative, which is exactly the weakness Kinetix can exploit. That only works if the three K6 objects have turntable or structured-light scans and the real runs report Chamfer, F-score and N@q, not pictures. Real flights should include at least `orbit_3ring`, `fvs`, `kinetix` (mono) and `stereo_plan`, so that the C2 decomposition appears on hardware.

Release planning should start now, not at submission. The field's impact pattern follows released pools, code and baselines (Bag of Views VPT, MA-SCVP, UrbanScene3D, ObjView-Bench's promised release; [Delmerico et al.](https://infoscience.epfl.ch/record/228469), [UrbanScene3D](https://www.ecva.net/papers/eccv_2022/papers_ECCV/html/3218_ECCV_2022_paper.php)). Asset licences (SimReady/Omniverse, Objaverse, GSO) decide which rendered pools can be redistributed, so they should be checked before the object set is fixed.

Finally, a watch list belongs in `docs/todo.md`. It should include ObjView-Bench's code release (it may set the default object pool), ActMVS's code (TrickyGo/ActMVS; a possible monocular baseline), the AREA3D backbone (CVPR 2026, an active agent on feed-forward 3D perception whose sensors and platform were not verified ([AREA3D](https://arxiv.org/abs/2512.05131))), and any Sep–Oct 2026 preprint on Isaac Sim + PX4 NBV, which these searches covered only thinly.

## Conclusion

The search changes what kind of paper Kinetix is. It is not best sold as a better planner that saves images; that ground is crowded, and the reported savings already bracket the target. It is a **measurement paper with a principled monocular method attached**. It is the first to ask, on one planner and one drone, *what depth is actually for* in object photogrammetry — choosing views or building the model — and it shows how much NBV conclusions drawn in replay survive PX4 dynamics and a real room. If hypothesis H1 holds, the monocular method becomes the justified design choice rather than a constraint. If it fails, the 2×2 still produces a publishable, quantified cost-of-stereo result. Either outcome is novel; a lone "62 % fewer images" is not.

Two uncertainties remain. Coverage of late-2026 preprints and of venues not indexed on arXiv was thin, so the "open" verdicts in the claims table are absence-of-evidence findings and need a final sweep before submission. Several sensor and platform details of the competitors (GauSS-MI's real platform, Hestia's code release, GenNBV's input modality) were not confirmed from full texts. The most time-sensitive risk is ObjView-Bench: once its code and object pool are public, Kinetix results that cannot be mapped onto its protocol will look isolated, which is why the Tammes-pool and shared-object changes should land in K1–K2 rather than at write-up.
