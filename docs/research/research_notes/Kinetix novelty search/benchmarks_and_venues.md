# NBV / Active Object Reconstruction: Benchmarks, Datasets, Protocols and Venues (2020-2026) for Kinetix

Research date: 2026-10-08. Budget: ~16 tool calls (web search/fetch). Items marked **[unverified]** come from background knowledge and were NOT confirmed by a fetched source in this session. Treat them as leads to check, not as facts.

## 1. Existing NBV / active object reconstruction benchmarks and datasets, and their protocols

### Takeaway
Object-level NBV has no single accepted benchmark. Every group builds its own protocol on mesh repositories (ShapeNet/ModelNet, Stanford 3D, Houses3K, OmniObject3D, Objaverse). Views are usually a **discrete view sphere** (32-33 views in PC-NBV/SCVP-style work, now 128/360 Tammes points in ObjView-Bench), rendered with depth/point clouds rather than photoreal RGB. Metrics are mostly **surface coverage plus view count and path cost**, with Chamfer only sometimes. The closest thing to a standard is the newest one, **ObjView-Bench (Pan, Bennewitz et al., arXiv May 2026)**: depth/geometry, view sphere, no drones, and code promised only on acceptance. Continuous-action RL benchmarks (GenNBV, CVPR 2024) run in Isaac Gym on Houses3K/OmniObject3D, report coverage/AUC/Chamfer, and are simulation-only.

### Cited Findings

**ObjView-Bench (most recent and most relevant competitor benchmark)**
- "ObjView-Bench: Rethinking Difficulty and Deployment for Object-Centric View Planning", Sicong Pan, Hao Hu, Xuying Huang, Benno Wingender, Maren Bennewitz (Uni Bonn), arXiv 2605.10707, submitted 2026-05-11 (cs.RO). Argues that "difficulty, budget, and reachability constraints substantially change method rankings and failure modes". It separates three things: object self-occlusion, observation-saturation difficulty, and set-cover planning difficulty — [arXiv abs](https://arxiv.org/abs/2605.10707)
- Objects: 5,691 from Objaverse++ after quality/geometry filtering (5,523 main pool + 168 "slow-saturation" diagnostic subset). It cites ShapeNet, Objaverse, the Stanford 3D Scanning Repository and Linemod as earlier sources — [arXiv HTML](https://arxiv.org/html/2605.10707)
- View space: the canonical protocol is a **128-view Tammes sphere**, with a 360-view Tammes set as dense reference. Reachability variants are "whole" (ideal sphere) and "quarter" (25% of the sphere). In their real tabletop arm setup only **45.4/128 candidate views are reachable on average** — [arXiv HTML](https://arxiv.org/html/2605.10707)
- Budgets: K=5, K=30, and an automatic map-stabilisation stop (1% gain over 3 consecutive steps, capped at 128). Metrics: Normalized Surface Coverage, Path Cost, #Views, Planning Runtime. No Chamfer/F-score, no photometric metrics, no SfM/3DGS pipeline (as summarised from the HTML) — [arXiv HTML](https://arxiv.org/html/2605.10707)
- Planners compared: Random+TSP, RSE, RSE-Mov (classical); NBV-Net, BENBV-Net, MA-SCVP (learned); PoinTr-C+NBV/SCP/MCP (hybrid, with shape completion) — [arXiv HTML](https://arxiv.org/html/2605.10707)
- Release: "we will release the object pool, benchmark code, and baseline implementations with the final version", so nothing is released yet — [arXiv HTML](https://arxiv.org/html/2605.10707)

**SCVP / MA-SCVP line (Bonn, Pan et al.)**
- SCVP (one-shot set-covering view planning) is published in IEEE RA-L 2022, DOI 10.1109/LRA.2022.3140449 (DOI from the search hit; title "SCVP: Learning One-shot View Planning via Set Covering for Unknown Object Reconstruction" **[title unverified, DOI seen]**) — [unpaywall DOI](https://unpaywall.org/10.1109%2FLRA.2022.3140449)
- MA-SCVP: "Integrating One-Shot View Planning with a Single Next-Best View via Long-Tail Multiview Sampling", Pan, Hu, Wei, Dengler, Zaenker, Dawood, Bennewitz, **IEEE T-RO 2024**. Trained on a multiview dataset generated by long-tail sampling; reports a 45% reduction in movement cost. Code at github.com/psc0628/MA-SCVP — [HRL Bonn](https://www.hrl.uni-bonn.de/publications/2024/pan24tro); [arXiv 2304.00910](https://arxiv.org/abs/2304.00910v1); [GitHub](https://github.com/psc0628/MA-SCVP)
- **[unverified]** Typical SCVP/PC-NBV protocol: 32-33 candidate views on a sphere around a normalised ShapeNet/ModelNet object, a simulated depth camera, and reporting of surface coverage vs number of views. The same Bonn group also published "How Many Views Are Needed..." (RA-L ~2024) — not fetched.

**PC-NBV, NBV-Net, Vasquez-Gomez**
- PC-NBV picks viewpoints directly from the object point cloud instead of voxel ray-casting. It is commonly evaluated on ShapeNet/ModelNet — [search summary pointing to Pred-NBV / related](https://arxiv.org/abs/2304.11465)
- NBV-Net ("Supervised Learning of the Next-Best-View for 3D Object Reconstruction", Mendoza, Vasquez-Gomez et al.) — [ResearchGate](https://www.researchgate.net/publication/339513000_Supervised_Learning_of_the_Next-Best-View_for_3D_Object_Reconstruction). **[unverified details]**: Pattern Recognition Letters 2020. Dataset of ~15k examples built from ModelNet10-type objects with a discrete 14-view sphere (Vasquez-Gomez view-sphere convention), released publicly.
- Next-best-view regression with a 3D CNN (Vasquez-Gomez group follow-up, arXiv 2101.09397) — [arXiv](https://arxiv.org/pdf/2101.09397)
- Boundary Exploration of NBV policy (BENBV-Net, arXiv 2412.10444), compared in ObjView-Bench — [arXiv](https://arxiv.org/pdf/2412.10444)
- PC-NBV original: **[unverified]** Zeng et al., IROS 2020, ShapeNet, 33 views.

**Isler/Delmerico ROS NBV framework (pre-2020 but still cited)**
- Delmerico, Isler, Sabzevari, Scaramuzza, "A Comparison of Volumetric Information Gain Metrics for Active 3D Object Reconstruction", Autonomous Robots 42(2):197-208, 2018 (ICRA 2016 conference version). Open-source modular ROS framework for NBV with a dense depth sensor — [EPFL infoscience](https://infoscience.epfl.ch/record/228469); [UZH RPG news](https://www.ifi.uzh.ch/en/rpg/news/Our-paper-on-Volumetric-Information-Gain-Metrics-for-Active-3D-Reconstruction-has-been-published-by-Autonomous-Robots-.html)

**Continuous-action / RL benchmarks (Houses3K, OmniObject3D, Objaverse)**
- GenNBV (Chen et al., **CVPR 2024**): NVIDIA **Isaac Gym** at ~1000 FPS. Houses3K (256 train / 50 test), OmniObject3D (43 house-category objects tested), Objaverse for visualisation/generalisation. **5-D continuous action space** (3D position in ~20x20x10 m + yaw/pitch), contrasted with earlier hemisphere-constrained setups. Metrics: final coverage ratio, mean AUC of the coverage curve, and Chamfer accuracy (cm). Baselines: random, hemisphere heuristics, information-gain methods, Scan-RL. 98.26% coverage on the Houses3K test set. **No real drone deployment** — [arXiv HTML](https://arxiv.org/html/2402.16174v2); [CVF](https://openaccess.thecvf.com/content/CVPR2024/papers/Chen_GenNBV_Generalizable_Next-Best-View_Policy_for_Active_3D_Reconstruction_CVPR_2024_paper.pdf)
- VIN-NBV (Frahm, Zhao, ..., Sengupta; arXiv 2505.06219, v3 Aug 2025): learns to predict "Relative Reconstruction Improvement" instead of coverage. ~30% better reconstruction than coverage-greedy and ~40% better than Scan-RL/GenNBV. Reports CD 0.20 cm on OmniObject3D houses with 20 acquisitions (per search snippet) — [arXiv](https://arxiv.org/abs/2505.06219)
- Hestia (Lu, ..., Sridhar, Lin; **WACV 2026**): continuous hierarchical NBV for objects. ≥4% coverage gain, 50% lower Chamfer, ≥12% better coverage with 5 images, and a claimed physical-world deployment demo — [arXiv](https://arxiv.org/abs/2508.01014); [project](https://johnnylu305.github.io/hestia)
- OmniObject3D: ~6,000 real-scanned objects in 190+ categories, used to test real-world transfer — [GenNBV / search summary](https://www.researchgate.net/publication/383240723_GenNBV_Generalizable_Next-Best-View_Policy_for_Active_3D_Reconstruction)

**Drone object NBV (simulation)**
- Pred-NBV (Dhami et al., RAAS lab): prediction-guided NBV that trades off information gain against control effort — [arXiv 2304.11465](https://arxiv.org/abs/2304.11465); [project](https://raaslab.org/projects/PredNBV/). **[unverified]**: evaluated in AirSim with a simulated UAV on ShapeNet-derived objects (IROS 2023).
- MAP-NBV: multi-agent, prediction-guided NBV for active 3D object reconstruction — [arXiv 2307.04004](https://arxiv.org/html/2307.04004v2). **[unverified]**: AirSim, ICRA 2024.
- Bag of Views (Gazani, Tucsok, Mantegh, Najjaran; **RA-L 2023**): appearance-based (image-only) NBV. Releases the **View Planning Toolbox (VPT)**, a lightweight package for training/testing ML view planners, generating datasets and running 3D reconstruction. Uses offline dataset refinement plus online NBV with RL — [arXiv](https://arxiv.org/abs/2307.05832)

**Radiance-field / 3DGS active view selection (scene and object)**
- NeU-NBV (image-based neural rendering uncertainty, limited budget). ActiveNeRF, FisherRF and Bayes' Rays are the usual baselines. Common datasets are **DTU** (15 scenes, 49-64 images, 384x384 in that protocol) and **NeRF Blender Synthetic** (8 scenes, 100 train / 200 test, 800x800). Metrics are PSNR/SSIM/LPIPS under a fixed view budget — [search summary incl. arXiv 2405.02568 / 2310.00684](https://arxiv.org/pdf/2405.02568)
- ActiveGAMER (**CVPR 2025**): 3DGS active mapping with rendering-based information gain — [CVF](https://openaccess.thecvf.com/content/CVPR2025/papers/Chen_ActiveGAMER_Active_GAussian_Mapping_through_Efficient_Rendering_CVPR_2025_paper.pdf)
- ActiveGS (Jin et al.) and ActiveSplat: both reported as **RA-L 2025** — [search summary / reference lists](https://arxiv.org/pdf/2504.21067)
- GauSS-MI (Xie, Cai, Zhang, Yang, Jia Pan; arXiv 2504.21067): Shannon MI per Gaussian for real-time view selection, targeting *visual quality* rather than geometric completeness, with simulated and real-world scenes — [arXiv](https://arxiv.org/abs/2504.21067). **[unverified]**: accepted at RSS 2025.
- More 2025-26 view-selection preprints: SA-ResGS (2601.03024), OUGS object-aware uncertainty in 3DGS (2511.09397), Camera Splatting continuous view optimisation (2509.15677), Coverage Optimization for Camera View Selection (2604.05259) — [arXiv 2601.03024](https://arxiv.org/pdf/2601.03024); [arXiv 2511.09397](https://arxiv.org/pdf/2511.09397); [arXiv 2509.15677](https://arxiv.org/pdf/2509.15677); [arXiv 2604.05259](https://arxiv.org/pdf/2604.05259)

**Aerial / scene-scale datasets**
- UrbanScene3D (Lin et al., **ECCV 2022**): >128k high-res images, 16 scenes, 136 km² total. 6 virtual CAD scenes and 5 real scenes reconstructed from drone images, with LiDAR GT. Built on Unreal + AirSim and pitched as a benchmark "to design and evaluate aerial path planning and 3D reconstruction algorithms". City scale, not object scale — [ECVA](https://www.ecva.net/papers/eccv_2022/papers_ECCV/html/3218_ECCV_2022_paper.php); [arXiv 2107.04286](https://arxiv.org/abs/2107.04286v2)
- OpenFlyScan (You et al., arXiv 2609.24253, 2026-09-21): outdoor consumer-drone 3DGS system that predicts poorly reconstructed regions and plans reacquisition flights. Reports +10.95 dB PSNR at the added views, with code/models promised. Outdoor, scene scale, PSNR only, no geometric GT — [arXiv](https://arxiv.org/abs/2609.24253)
- GRADE: Isaac Sim framework for richly annotated synthetic data from a flying drone in dynamic environments (SLAM/perception, not NBV) — [arXiv 2303.04466](https://arxiv.org/html/2303.04466v3)

**MVS datasets Kinetix will be compared against (not NBV benchmarks)**
- **[unverified, standard knowledge]** DTU (robot-arm structured light, 49/64 fixed views per scan; accuracy/completeness in mm), Tanks and Temples (laser-scanned GT; **F-score at a per-scene threshold τ**, which is the precedent for Kinetix's size-relative τ), BlendedMVS (synthetic-blended training data, no NBV protocol), Google Scanned Objects (~1k scanned household objects, mostly used for novel-view synthesis and sparse-view evaluation), Objaverse/Objaverse-XL (CAD at scale, varying quality, hence ObjView-Bench's Objaverse++ filtering). None of these defines a sequential view-selection protocol.

### Inferences
- The field's de facto protocol is "discrete view sphere + depth sensor + coverage vs #views". It is geometric and sensor-idealised: no photoreal RGB, no SfM failure modes, no flight dynamics.
- "Discrete view pool replay" (pre-render a dense candidate set, let the planner pick) is effectively how SCVP/PC-NBV/NBV-Net/ObjView-Bench already work, though they render depth on the fly or from meshes, not stored photoreal RGB pools. Kinetix's pre-rendered *photoreal RGB/stereo* pools are a fair, reproducible extension of that norm, not a departure from it. Calling it "replay" lets offline methods be compared with exact reproducibility, as NeRF view-selection work does with fixed DTU/Blender image sets.
- Kinetix's metric set (Chamfer + F-score@τ relative to object size + completeness + N@q) is richer than ObjView-Bench's (coverage/path/#views/runtime) and closer to the Tanks-and-Temples convention. N@q (images-to-quality) corresponds to GenNBV's AUC and ObjView-Bench's saturation stopping.

## 2. Is there a benchmark coupling realistic drone flight (PX4/SITL) + photoreal rendering + object-level GT for NBV? Is discrete view pool replay standard?

### Takeaway
No such benchmark turned up. The closest pieces are spread out: ObjView-Bench (object GT, discrete views, reachability, no drone, no photoreal), GenNBV (continuous drone-like action in Isaac Gym, no flight dynamics or real flights), UrbanScene3D (AirSim photoreal + real drone + LiDAR GT, but city scale), Pred-NBV/MAP-NBV (AirSim UAV, object-level, sim-only as far as checked), and OpenFlyScan/Hestia (real deployment, no GT benchmark). Discrete view sets are standard for object NBV. Photoreal pre-rendered RGB pools with flight-in-the-loop as a second tier are not.

### Cited Findings
- ObjView-Bench handles reachability by masking the view sphere ("whole" vs "quarter") and measures real-robot reachability (45.4/128 views) on a tabletop arm, not a drone. It has no flight dynamics and no photoreal SfM — [arXiv HTML](https://arxiv.org/html/2605.10707)
- GenNBV: Isaac Gym, continuous 5-DoF camera pose with no vehicle dynamics/autopilot. Experiments "remain simulation-based" — [arXiv HTML](https://arxiv.org/html/2402.16174v2)
- UrbanScene3D: Unreal/AirSim photoreal city scenes + real drone captures + LiDAR, explicitly a benchmark for aerial path planning and reconstruction, but at city scale — [arXiv 2107.04286](https://arxiv.org/abs/2107.04286v2)
- A targeted search for NBV + PX4 SITL/AirSim + real flights + Chamfer/F-score found no paper combining all of them (search-engine summary; the results contained no counter-example) — [Bag of Views](https://arxiv.org/pdf/2307.05832), [VIN-NBV](https://arxiv.org/pdf/2505.06219), [Hestia](https://arxiv.org/pdf/2508.01014) were the closest hits
- PX4 officially supports SITL with AirSim (Unreal) and Gazebo, so a PX4+photoreal sim is not new in itself. The novelty would be wrapping it into an object-NBV benchmark — [PX4 AirSim docs](https://docs.px4.io/main/en/sim_airsim/index)
- Isaac Sim drone datasets so far target perception/SLAM (GRADE), not NBV — [arXiv 2303.04466](https://arxiv.org/html/2303.04466v3)

### Inferences
- A three-tier protocol (discrete photoreal view-pool replay → continuous Isaac rendering → full PX4 SITL flight → real indoor flights with scanned GT) is, as far as these searches show, unoccupied. Its value is that it **measures the sim-to-real degradation of NBV rankings across tiers**. ObjView-Bench makes the same "rankings change under deployment constraints" argument, but only for arm reachability.
- ObjView-Bench is the strongest framing ally and the main novelty risk: same problem framing (object-centric, difficulty, budgets, deployment), a well-known group (Bennewitz), and an imminent code release. Kinetix should cite it and present itself as the **aerial, photoreal, monocular-RGB/SfM** complement (ObjView-Bench is depth/coverage-based).

### Gaps
- Could not exhaustively rule out a 2026 preprint on Isaac Sim + Pegasus/PX4 NBV; search coverage of Sep-Oct 2026 arXiv is thin.
- Did not check AirSim-based object datasets from Pred-NBV/MAP-NBV for release status.

## 3. Venues and recent acceptances (2023-2026) for active reconstruction / NBV with drones; what they emphasise

### Takeaway
Robotics venues (RA-L, often with an ICRA/IROS presentation option, plus T-RO and RSS) carry most object-NBV and active-3DGS work and reward real-robot validation and open code. Vision venues (CVPR/ICCV/ECCV/WACV/3DV) take learned NBV policies and benchmarks evaluated on large object sets (GenNBV, ActiveGAMER, Hestia, UrbanScene3D).

### Cited Findings
- RA-L: SCVP (2022) — [DOI](https://unpaywall.org/10.1109%2FLRA.2022.3140449); Bag of Views (2023, with toolbox release) — [arXiv](https://arxiv.org/abs/2307.05832); ActiveGS and ActiveSplat (2025) — [reference list via search](https://arxiv.org/pdf/2504.21067); semantic-aware receding-horizon object-centric active mapping (2024) — search summary, **[details unverified]**
- T-RO: MA-SCVP (2024) — [HRL Bonn](https://www.hrl.uni-bonn.de/publications/2024/pan24tro)
- CVPR: GenNBV (2024) — [CVF](https://openaccess.thecvf.com/content/CVPR2024/papers/Chen_GenNBV_Generalizable_Next-Best-View_Policy_for_Active_3D_Reconstruction_CVPR_2024_paper.pdf); ActiveGAMER (2025) — [CVF](https://openaccess.thecvf.com/content/CVPR2025/papers/Chen_ActiveGAMER_Active_GAussian_Mapping_through_Efficient_Rendering_CVPR_2025_paper.pdf); DroneSplat (CVPR 2025, drone in-the-wild 3DGS, not NBV) — search summary
- WACV 2026: Hestia, which stresses large training data, continuous viewpoints and a physical-world deployment demo — [arXiv](https://arxiv.org/abs/2508.01014)
- ECCV 2022: UrbanScene3D, a dataset/benchmark paper for aerial planning + reconstruction — [ECVA](https://www.ecva.net/papers/eccv_2022/papers_ECCV/html/3218_ECCV_2022_paper.php)
- Autonomous Robots: Delmerico/Isler comparison + open ROS framework (2018) — [EPFL](https://infoscience.epfl.ch/record/228469)
- **[unverified]** FisherRF at ECCV 2024; GauSS-MI at RSS 2025; Pred-NBV at IROS 2023; MAP-NBV at ICRA 2024; NeU-NBV at IROS 2023. ISPRS P&RS publishes UAV photogrammetry view planning (e.g., aerial path planning for urban reconstruction), but no specific 2023-26 NBV paper was verified this session.
- Emphasis pattern visible in abstracts: the robotics papers lead with real-robot/field validation and movement/path cost (MA-SCVP "45% reduction in movement cost"; ObjView-Bench real-tabletop reachability; OpenFlyScan field PSNR gains) and with tool/code release (Bag of Views VPT, MA-SCVP GitHub). The vision papers lead with generalisation across object datasets and comparisons against many learned baselines (GenNBV, VIN-NBV) — sources as above.

### Inferences
- RA-L reviewers will expect a real-flight experiment, comparison against established NBV baselines (at least random/uniform-sphere, an information-gain volumetric planner, and one learned planner such as SCVP/MA-SCVP or GenNBV), and released code. A benchmark-heavy paper with real data also fits the RA-L "dataset/benchmark" style.
- CVPR/ICCV/3DV reviewers would expect scale (hundreds or thousands of objects), learned baselines, and photometric + geometric metrics. Flight realism counts for less there.

### Gaps
- Acceptance rates and the RA-L dataset-paper policy were not fetched.
- No verified ISPRS P&RS or CoRL NBV-for-drone paper from 2023-26 was retrieved; treat those venues as plausible but unconfirmed.

## 4. Release norms: what made NBV papers impactful

### Takeaway
Impact follows released, reusable artefacts: open frameworks (Isler/Delmerico ROS NBV), datasets/generators (NBV-Net dataset, SCVP/MA-SCVP code + data, Bag-of-Views VPT, UrbanScene3D) and object pools (ObjView-Bench, pending). ObjView-Bench shows that newer benchmarks are expected to ship object pools + baseline implementations.

### Cited Findings
- Delmerico/Isler released an open-source modular framework "adaptable to other robotic platforms" — [EPFL](https://infoscience.epfl.ch/record/228469)
- MA-SCVP code is public on GitHub — [GitHub](https://github.com/psc0628/MA-SCVP)
- Bag of Views ships the View Planning Toolbox (training, testing, dataset generation, reconstruction) — [arXiv](https://arxiv.org/abs/2307.05832)
- UrbanScene3D is public at vcc.tech/UrbanScene3D with sim + real + LiDAR — [ECVA](https://www.ecva.net/papers/eccv_2022/papers_ECCV/html/3218_ECCV_2022_paper.php)
- ObjView-Bench promises an object pool, benchmark code and baselines at publication — [arXiv HTML](https://arxiv.org/html/2605.10707)
- OpenFlyScan and Hestia promise or host code/models on project pages — [OpenFlyScan](https://arxiv.org/abs/2609.24253); [Hestia](https://arxiv.org/abs/2508.01014)

### Inferences
- For Kinetix, the minimum release that matches the field's norm is: (a) view pools (RGB + stereo + poses + intrinsics) for a fixed object set, (b) GT meshes with normalisation and τ conventions, (c) evaluation scripts for Chamfer, F@τ, completeness and N@q, (d) baseline planners (random, uniform, volumetric IG, one learned), and (e) the Isaac/PX4 environment (Docker). The real-flight logs and images with scanned GT would be the scarcest and therefore most cited part.
- Isaac Sim asset licensing (SimReady/Omniverse assets, Objaverse/GSO licences) has to be checked before redistributing rendered pools.

## Benchmark/dataset novelty opportunity for Kinetix

- **Open gap, as far as these searches show:** no public benchmark combines (i) object-level GT, (ii) photoreal RGB (mono + stereo) for SfM/3DGS-based NBV, (iii) a drone with real autopilot dynamics (PX4 SITL) in the loop, and (iv) real indoor flights of the same objects with scanned GT. Existing work covers one or two of these at a time:
  - ObjView-Bench: object GT, discrete views, reachability, real tabletop arm; no drone, no photoreal SfM, nothing released yet.
  - GenNBV / VIN-NBV / Hestia: object sets with continuous views; simulation or a demo only.
  - UrbanScene3D: photoreal sim + real drone + LiDAR, but city scale.
  - Pred-NBV / MAP-NBV: AirSim UAV at object scale; sim-only **[real flights unverified]**.
  - OpenFlyScan / GauSS-MI: real platforms; scene scale, photometric metrics only.
- **Closest competitors to position against:** ObjView-Bench (framing, protocol), GenNBV (drone-like continuous NBV in Isaac), and UrbanScene3D (sim+real aerial benchmark precedent).
- **Defensible contributions:**
  1. A **tiered protocol** (pool replay → continuous render → PX4 SITL → real flight) that quantifies how NBV rankings and N@q shift across realism tiers. This is the aerial/photoreal analogue of ObjView-Bench's "deployment changes rankings" claim.
  2. **Size-relative F-score@τ + N@q**, following the Tanks-and-Temples F-score convention, in place of coverage-only metrics.
  3. A **controlled monocular-vs-stereo study** under identical view pools. No NBV benchmark seen here isolates sensor modality this way.
  4. A released **sim-to-real indoor object set** (digital twins of the physically flown objects).
- **Risks:** ObjView-Bench's release may set the community default for object pools. Make Kinetix's object set compatible (e.g., include Objaverse++ / GSO / OmniObject3D items and a 128-view Tammes pool variant) so results can be cross-referenced. The real-flight subset needs reliable GT (turntable/structured-light scans) or reviewers will discount it.

## Recommended venue(s) with rationale

1. **IEEE RA-L (with an ICRA or IROS presentation option)**: primary recommendation. It is where SCVP (2022), Bag of Views (2023), ActiveGS/ActiveSplat (2025) appeared, and Bonn's T-RO/RA-L line is the closest competitor community. RA-L reviewers value exactly the "system + real-robot validation + open-source + benchmark" mix. Expect them to ask for real flights with quantitative GT, comparisons against SCVP/MA-SCVP-, GenNBV- and volumetric-IG-type baselines, path/flight-time cost as well as reconstruction quality, ablations, and a code/data release.
2. **CVPR/ICCV/ECCV Datasets & Benchmarks-style or 3DV**: secondary option, if the dataset is large (hundreds+ objects, many pools) and the mono-vs-stereo + SfM/3DGS evaluation is the headline. Precedents are GenNBV (CVPR 2024), ActiveGAMER (CVPR 2025) and UrbanScene3D (ECCV 2022). Reviewers there want scale, learned baselines and photometric + geometric metrics, and give less weight to PX4 realism.
3. **T-RO**: for a later, consolidated version with longitudinal real-world results (MA-SCVP precedent).
4. **ISPRS P&RS**: a fit if the photogrammetric accuracy (COLMAP/3DGS, mono vs stereo, τ-relative metrics) is the main contribution. No 2023-26 drone object-NBV acceptance there was verified this session.
